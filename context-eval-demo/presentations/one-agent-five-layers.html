The setup

One agent, REVENUE_ASSISTANT. Each version adds exactly one layer. The model and base instructions never change, so a change in score comes from the layer.

Version aliasAddsFeature
V0_STUFFEDAnalyst over an auto-generated semantic view: 38 tables, 140 columns, lookalike metricsanti-pattern
V1_GOVERNED_SVAnalyst over a 5-table star: certified ARR metric, one verified querySemantic view
V2_ONTOLOGYSearch over governed business definitions, each bound to a semantic view memberBusiness Ontology
V3_SENSEContext learned from the core tables, the semantic view and analysts' query historyCortex Sense
V4_INSTRUCTIONSOne policy instruction: no named rep rankings for performance plansInstructions

Versions are immutable and called by alias, for example REVENUE_ASSISTANT!V2_ONTOLOGY. The same alias drives the live demo, the Streamlit app and each eval run.

Start with a small governed semantic view. Going from V0 to V1 nearly doubles correctness while using 18% fewer tokens. That is the only step that improves both. Add the ontology, Sense or instructions only when an eval question that the layer should fix keeps failing.

Why each layer moved the score

V1  Governed semantic view

A certified ARR metric (12 × MRR of active Subscription lines) and a verified query take away the choice of which table and which filter. The 31 lookalike tables are no longer visible to the agent.

ARR 0.58 → 1.00 · EMEA drop 0.17 → 0.84 · tokens −18%

V2  Business Ontology

"Bookings" now has one governed meaning, bound to the semantic view's net-new ACV metric and explicitly marked as not the same as TCV Bookings. The agent reads the definition before it queries.

Bookings 0.92 → 1.00, right by construction rather than by luck

V3  Cortex Sense

The semantic view doesn't model partner referrals. Sense learned from query history that analysts join accepted referrals, not the stale lead-source field, so the agent stops answering 9.

Partner deals 0.00 → 0.67 · costs ~19K more tokens per question

V4  One instruction

No context layer fixes behavior. Every earlier version ranked reps more accurately. One policy sentence makes the agent decline and offer an aggregate view.

Rep ranking 0.00 → 1.00

Run it yourself

You need the Snowflake CLI and Python 3.9+. Nothing to pip install. The install takes about 4 minutes into any account.

1 · Install data, semantic views, ontology, the agent and its versions, and the app
python3 scripts/deploy.py -c <connection> --role SYSADMIN --warehouse <WH>
2 · Optional: build the Cortex Sense context (see setup/CORTEX_SENSE.md), then add V3
python3 scripts/deploy.py -c <connection> --steps agent
3 · Optional: score every version in your own account (10–25 min)
python3 scripts/run_evals.py -c <connection>

Then open Snowsight → Projects → Streamlit → CONTEXT_EVAL_DEMO_APP. It has the story, live side-by-side answers from any two versions, eval results, and each version's spec and the ontology. If Business Ontology or Cortex Sense isn't enabled, those versions are skipped and the rest still work.

Takeaways

Start small and governed

A 5-table semantic view beat a 38-table one on correctness and cost. Stuffing more context in is the most expensive way to be wrong.

Match the layer to the failure

Contested meaning needs a definition (ontology). The long tail needs learned usage (Sense). Behavior needs an instruction. None of them substitutes for another.

Let evals decide

Tag every change as a version, score it on questions built to fail, and keep a layer only if it moves the score enough to justify its tokens.
