Why Descriptions Matter

Descriptions are the bridge between your data model and AI comprehension

Cortex Analyst Accuracy

Cortex Analyst reads descriptions to understand what dimensions, facts, and metrics mean. Poor descriptions lead to incorrect SQL generation and wrong answers.

Business User Trust

When Cortex Analyst generates wrong queries, business users lose trust. Clear descriptions prevent ambiguity that causes misinterpretation.

Discoverability

Good descriptions help users find the right metrics. "Revenue" could mean gross, net, recognized, or deferred -- the description disambiguates.

Maintenance at Scale

As semantic views grow to hundreds of elements, descriptions serve as living documentation that prevents knowledge silos.

The Four Grading Criteria

Every description is evaluated on four independent axes

Precise
Specific enough to distinguish from similar concepts
Concise
No unnecessary words or filler language
Non-Circular
Does not restate the name as the definition
Correct
Accurately reflects the underlying SQL expression

1. Preciseness

Can this description uniquely identify what this element computes?

Failing

Metric: TOTAL_REVENUE

"The total revenue"

Does not specify: gross vs net, what time grain, which business line, or whether discounts are applied.

Passing

Metric: TOTAL_REVENUE

"Sum of extended price after applying line-item discounts, across all order statuses. Does not include tax or shipping."

Specifies the calculation basis, discount treatment, scope, and exclusions.

Key question: If a user has two similarly-named metrics, could they tell them apart from descriptions alone?

2. Conciseness

Does every word earn its place in the description?

Failing

Dimension: ORDER_DATE

"This field represents the date on which the order was placed by the customer in the system and recorded in the database"

27 words. "This field represents", "by the customer", "in the system", "and recorded in the database" are all filler.

Passing

Dimension: ORDER_DATE

"Date the order was placed"

5 words. Same information, no filler. Cortex Analyst parses this faster and more reliably.

Common anti-patterns: Starting with "This is the...", "This field represents...", "This column contains...", or ending with "...in the database", "...in the system".

3. Non-Circular

Does the description add information beyond what the name already says?

Failing

Fact: DISCOUNTED_PRICE

"The discounted price"

This is just the name with articles added. It tells the AI nothing it couldn't already infer.

Passing

Fact: DISCOUNTED_PRICE

"Extended price multiplied by (1 - discount rate). Represents per-line-item revenue after discount but before tax."

Explains the formula, clarifies scope (per line item), and states what is excluded (tax).

The test: Delete the element name. Does the description still convey meaning on its own? If you need the name to understand the description, it's circular.

4. Correctness

Does the description accurately reflect the underlying SQL expression?

Failing

Metric: ORDER_AVERAGE_VALUE

Expression: AVG(orders.o_totalprice)

"Total value of all orders"

Says "total" but the expression uses AVG. This will confuse the AI into double-aggregating or misinterpreting user questions about averages.

Passing

Metric: ORDER_AVERAGE_VALUE

Expression: AVG(orders.o_totalprice)

"Average total price per order across all orders"

Correctly identifies the aggregation (average), the measure (total price), and the grain (per order).

Validation method: Compare the description against the SQL expression. The aggregation type, included columns, filters, and grain must all match.

Grading Rubric

Each criterion is scored independently, then combined

GradePrecisenessConcisenessNon-CircularCorrectness
A Uniquely identifies the element; includes scope, exclusions, and edge cases Every word is necessary; under 20 words for simple elements Description is entirely independent of the name Perfectly matches the SQL expression including aggregation and filters
B Mostly specific; minor ambiguity that wouldn't cause misuse 1-2 filler words but core meaning is tight Adds substantial information beyond the name Correct aggregation and grain; minor omissions on edge cases
C Generic; could apply to multiple elements in the view Noticeably verbose; could be 50% shorter Partially restates the name but adds some new info Right concept but wrong aggregation type or missing key detail
D Vague; provides almost no distinguishing information Extremely verbose; buries meaning in boilerplate Mostly just restates the name with filler words Misleading; would cause incorrect AI-generated queries
F Missing or completely generic ("a metric") N/A (missing description) Exact copy of element name or trivial rewording Contradicts the actual expression

Automating Review with Cortex Code

The semantic-view skill provides automated description quality analysis

Skill Invocation

Cortex Code's semantic-view skill automatically loads when working with semantic view YAML or SQL definitions. It grades descriptions across all four criteria without manual prompting.

Expression-Aware

The skill reads the SQL expression for each element and validates that the description accurately reflects the computation, catching "says SUM but uses AVG" errors.

Batch Analysis

Review an entire semantic view at once. The skill produces a per-element scorecard covering all dimensions, facts, and metrics with specific improvement suggestions.

Fix-in-Place

After identifying issues, Cortex Code can rewrite descriptions directly in your YAML or DDL, applying all four criteria simultaneously. You review and approve the changes.

Next Steps

Audit Your Existing Views

Run the semantic-view skill against your production semantic views to identify descriptions scoring below B on any criterion. Prioritize metrics and customer-facing dimensions.

Establish a Standard

Adopt the four-criteria rubric as part of your semantic view development process. Add description review to PR checklists and CI pipelines.

Measure Analyst Accuracy

Track Cortex Analyst accuracy before and after description improvements. Strong descriptions correlate directly with fewer incorrect query generations.

Automate with Cortex Code

Integrate Cortex Code description review into your development workflow. Catch description regressions before they reach production.

Key takeaway: Descriptions are not documentation -- they are instructions to the AI. Treat them with the same rigor as your SQL expressions.
