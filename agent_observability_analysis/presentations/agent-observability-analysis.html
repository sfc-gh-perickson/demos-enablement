Agent Observability & Analysis

How to mine production agent interactions into evaluation datasets that drive continuous improvement

The Problem

You deployed an agent. Users are interacting with it. Some are happy, some aren't. How do you systematically find and fix the failures?

The Approach

Mine observability data for three types of signal — explicit feedback, implicit rephrasing, and intent trends — to build targeted evaluation datasets.

The Outcome

An automated pipeline that continuously tests your agent on its real weak spots, not hypothetical ones. Every interaction makes the next version better.

Three Mining Techniques

Each technique extracts a different type of improvement signal from the same observability table.

1

Explicit Feedback

Filter for CORTEX_AGENT_FEEDBACK events. Extract the feedback_message text alongside the positive/negative signal. Join back to the original query via a mapping table.

High priority Sparse signal
2

Implicit Rephrase Detection

Find multi-turn threads where the follow-up is semantically similar to the first message. Use a two-step filter: embedding similarity + LLM confirmation to distinguish frustration from follow-up.

Medium priority Dense signal
3

Intent Classification

Classify all queries into intent categories using CORTEX.COMPLETE. Cross-reference with feedback rates to identify which intents have the highest failure rate — focus improvement there.

Low priority Coverage
Key principle: In production, ~80% of queries receive no explicit feedback. Implicit signals (rephrases, abandonment) unlock evaluation signal from the silent majority of users who never click thumbs down.

Rephrase Detection: Technical Flow

The two-step approach achieves high precision by filtering out legitimate follow-up questions.

Step 1: Embedding Similarity Filter

For each turn where parent_message_id > 0, compare it against first_message_in_thread. Pairs exceeding a cosine similarity threshold (0.6) proceed to step 2.

VECTOR_COSINE_SIMILARITY( SNOWFLAKE.CORTEX.EMBED_TEXT_768( 'snowflake-arctic-embed-m-v1.5', FIRST_MSG)::VECTOR(FLOAT,768), SNOWFLAKE.CORTEX.EMBED_TEXT_768( 'snowflake-arctic-embed-m-v1.5', CURRENT_MSG)::VECTOR(FLOAT,768) ) > 0.6

Step 2: LLM Intent Confirmation

CORTEX.COMPLETE classifies the pair as REPHRASE (user unsatisfied, same question reworded) or FOLLOW_UP (genuinely new question building on the topic). Only confirmed rephrases become eval candidates.

SNOWFLAKE.CORTEX.COMPLETE('mistral-large2', 'Two messages from same user: Msg 1: ' || FIRST_MSG || ' Msg 2: ' || CURRENT_MSG || ' REPHRASE or FOLLOW_UP?' )
Why not similarity alone? "What was Q4 ROI?" followed by "And how does Q3 compare?" scores high similarity (same topic) but is a legitimate follow-up. "What was Q4 ROI?" followed by "I meant ROI broken down by channel specifically" is a rephrase indicating dissatisfaction. The LLM distinguishes these.

Assembling the Evaluation Dataset

All three mining sources feed into a single prioritized table, then ground truth is auto-generated for each candidate.

Source Priority What it captures Selection Logic
Explicit Negative High Known failures with user explanation of what went wrong All thumbs-down with non-empty feedback_message
Implicit Rephrase Medium Frustration signal from the silent majority Similarity > 0.6 AND LLM confirms REPHRASE
Intent Sample Low Broad coverage across all usage patterns 3 random queries per classified intent

Ground Truth Generation

CORTEX.COMPLETE generates a JSON object with ground_truth_output (expected answer) and expected_tools (which tools should be called). The prompt incorporates the user's feedback text so the ground truth addresses the specific gap.

Deduplication & Human Review

Dataset is deduplicated by query text, keeping the highest-priority source. Auto-generated ground truth is a draft — a human SME reviews and refines the top candidates before running evals.

Running the Evaluation

The mined dataset feeds directly into Snowflake's native EXECUTE_AI_EVALUATION to score the agent.

Built-in Metrics

answer_correctness and logical_consistency — LLM-as-judge scoring out of the box, no custom prompts needed.

Custom Metrics

Define your own metric with a prompt template. Here we score tool selection by comparing expected vs. actual tools from the trace.

Per-Source Analysis

JOIN eval results back to the mining source table to see which signal type surfaces the hardest questions — validating that the mining approach works.

The validation loop: If negative-feedback-sourced questions consistently score lowest, the mining is working — you're successfully surfacing real failure modes, not testing the agent on things it already does well.

From Evaluation to Improvement

Classifying negative feedback with CORTEX.COMPLETE reveals systemic patterns that map directly to improvement actions.

Issue Category What it means Improvement Lever Speed
Missing Detail Agent gave a partial answer, didn't retrieve the right context Enrich Cortex Search corpus; add verified queries to semantic view Days
Wrong Answer Agent confused concepts or returned incorrect calculations Refine orchestration instructions; add semantic view constraints Immediate
Format Issue Answer content was correct but presentation was wrong Update response instructions with explicit formatting rules Immediate
Scope Error Agent attempted to answer something outside its capability Add guardrails in orchestration to decline gracefully Immediate
Tool Selection Error Agent used the wrong tool or didn't combine tools when needed Refine orchestration instructions; clarify tool descriptions Immediate
The classification prompt: CORTEX.COMPLETE('mistral-large2', 'Classify this feedback: WRONG_ANSWER, MISSING_DETAIL, FORMAT_ISSUE, TOOL_SELECTION_ERROR, SCOPE_ERROR, HALLUCINATION. Feedback: ' || feedback_message) — simple, fast, and gives you a distribution you can act on.

Closing the Loop

The observability-to-evaluation pipeline turns agent usage data into a compounding improvement engine.

Observe Continuously

Every interaction is captured automatically. No instrumentation code, no separate logging system. GET_AI_OBSERVABILITY_EVENTS provides full access.

Mine Periodically

Schedule mining with a Snowflake Task. As new feedback accumulates, the eval dataset grows organically — always testing the agent's real weak spots.

Evaluate on Every Change

Before promoting agent versions, run the mined eval dataset as a regression gate. Improvements prove themselves against actual failure modes.

The key differentiator: Business data, observability data, and evaluation data all in one governed platform.
No ETL. No integration lag. No governance gaps. Just a flywheel that compounds.
