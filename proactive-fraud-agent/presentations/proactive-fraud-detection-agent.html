The Problem: Reactive Investigation

Today's Workflow

  • Data flows in across products
  • Exceptions generated by rules engine
  • Work items assigned to investigators
  • Analyst pulls up a dashboard or case
  • AI analyzes only AFTER human looks

Proactive Workflow

  • Data flows in and is featurized in real-time
  • ML model scores and explains every customer
  • Agent investigates top priorities autonomously
  • Reports surface with full conversation context
  • Analyst picks up mid-investigation, not from zero
Key Shift: The agent sits in Steps 1-3 of the pipeline (ingestion, intelligence, scoring) — not Step 4 (post-investigation). It finds patterns before a human goes looking.

Pipeline Stages

Stage 1   Foundations

500K synthetic transactions with 5 injected fraud patterns: velocity spikes, structuring, geographic anomalies, return abuse, and new merchant fraud.

Stage 2   Feature Pipeline

Dynamic Tables compute per-customer aggregates across 1h/24h/7d windows. Incremental refresh with 5-minute target lag.

Stage 3   Feature Store

Snowflake ML Feature Store SDK registers a CUSTOMER entity and FRAUD_FEATURES view with managed refresh.

Stage 4   ML Inference

XGBoost classifier trained on labeled fraud patterns. SHAP TreeExplainer computes per-customer feature attributions.

Stage 5   Prioritization

Top 100 customers scored above threshold, ranked by fraud probability, with SHAP explanations attached.

Stage 6   Agent Investigation

Cortex Agent autonomously investigates each priority. Writes structured reports with thread_id for conversation continuity.

XGBoost + SHAP: Explainable Scoring

Model Training

XGBClassifier from snowflake.ml.modeling trained on Feature Store output. Labels derived from injected fraud patterns (velocity, structuring, geo anomaly).

SHAP Explainability

TreeExplainer computes per-customer SHAP values. Stored as JSON array: [{feature, shap_value, direction}]. Powers the waterfall chart in the portal.

Model Registry

Logged as FRAUD_DETECTOR V1 in Snowflake Model Registry. predict_proba method available for batch inference via SQL.

SHAP Output Example:

Full investigation narrative rendered as rich text. Includes pattern analysis, severity assessment, and specific transaction concerns.

Chat Continuation

Live chat panel using thread_id from the reports table. Analysts continue the agent's investigation with full prior context preserved.

Thread Continuity: The Key Differentiator

How it works:

1. Agent investigates a priority via DATA_AGENT_RUN(..., TRUE) — creates a thread

2. Response includes thread_id in metadata — stored in INVESTIGATION_REPORTS

3. React portal reads thread_id and passes it to subsequent DATA_AGENT_RUN calls

4. Analyst picks up exactly where the agent left off — full conversation history preserved
User Experience: An analyst opens the portal, sees "Customer CUST_004200 flagged for VELOCITY pattern (0.94 probability)." They click in, read the agent's report, then ask: "Show me the specific transactions between 2-3am that triggered this." The agent already knows the context.
