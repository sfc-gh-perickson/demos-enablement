The Problem

Agents need the same rigor as production code

No Automated Testing

Agent changes deployed without validation. Regressions in answer quality go unnoticed until users report issues.

Manual Deployments

Ad-hoc SQL scripts run by hand. Different environments drift out of sync. No audit trail of what changed.

Disconnected Data Layer

Schema changes in the data layer break agents silently. No pipeline ties model changes to agent redeployment.

Goal: Treat the full stack — dbt models, semantic views, and Cortex Agent — as a single deployable unit with automated quality gates.

Environment Isolation: generate_schema_name macro routes models to AGENT_CICD_DEV or AGENT_CICD_PROD databases via dbt targets.

Semantic View

The bridge between data and natural language

-- models/semantic/retail_analytics.sql
{{ config(materialized='semantic_view') }}

TABLES(
    customers AS {{ ref('dim_customers') }},
    products  AS {{ ref('dim_products') }},
    orders    AS {{ ref('fct_orders') }}
)
RELATIONSHIPS(
    orders.customer_id REFERENCES customers.customer_id
)
FACTS(
    orders.order_total      AS order_total,
    customers.lifetime_orders AS customer_lifetime_orders,
    products.total_units_sold AS product_units_sold
)
DIMENSIONS(
    customers.customer_name AS customer_name SYNONYMS ('customer', 'buyer'),
    products.category       AS product_category SYNONYMS ('category', 'department'),
    orders.order_date       AS order_date SYNONYMS ('purchase date')
)
METRICS(
    total_revenue      AS SUM(orders.order_total),
    average_order_value AS AVG(orders.order_total),
    total_orders       AS COUNT(orders.order_id)
)
dbt_semantic_view package: Materializes as a native Snowflake semantic view. Synonyms and comments enable the agent to understand user intent expressed in natural language.

Cortex Agent

Retail analytics Q&A powered by the semantic view

CREATE OR REPLACE AGENT SEMANTIC.RETAIL_ASSISTANT
    MODEL = 'claude-3-5-sonnet'
    INSTRUCTIONS = '
You are a retail analytics assistant. You help users
answer questions about customers, orders, products,
and revenue using structured data.

Guidelines:
- Always provide specific numbers for quantitative questions
- Format currency values with $ and two decimal places
- When discussing trends, reference specific date ranges
'
    TOOLS = (
        ANALYST_TOOL(
            SEMANTIC_VIEW => 'SEMANTIC.RETAIL_ANALYTICS',
            DESCRIPTION => 'Query retail data including
                customers, orders, products, and revenue.'
        )
    );
Single tool, full coverage: The ANALYST_TOOL backed by a well-defined semantic view handles all data questions without needing multiple tools or complex routing.

CI Pipeline

Runs on every Pull Request

1
dbt Build & Test (Dev)
Seeds data, runs all models, executes dbt tests against AGENT_CICD_DEV
2
Semantic View Validation
Confirms the view exists and has all expected components: TABLE, DIMENSION, FACT, METRIC, RELATIONSHIP
3
Agent Evaluation
Deploys agent to dev, runs evaluation dataset (12 questions across 4 categories), checks score thresholds
Gate: If any evaluation metric falls below its threshold, the PR is blocked from merging.

CD Pipeline

Runs on merge to main

1
dbt Build (Prod)
Full seed + run + test cycle against AGENT_CICD_PROD database
2
Deploy Cortex Agent
CREATE OR REPLACE AGENT with production semantic view reference
3
Deployment Summary
Writes confirmation to GitHub Step Summary for audit trail
Zero manual steps: Merge triggers full production deployment automatically. The agent is live within minutes of approval.

Agent Evaluation

Automated quality gates with score thresholds

Metric Threshold What It Measures
Tool Selection Accuracy 0.80 Agent correctly selects ANALYST_TOOL for data questions
Answer Correctness 0.60 Response content matches expected answer semantics
Logical Consistency 0.70 Reasoning is coherent across multi-step responses

Evaluation Dataset

12 test questions across 4 categories: revenue, customers, orders, and products. Stored as a Snowflake table for easy iteration.

Evaluation Runner

Python script calls CORTEX.RUN_EVALUATION(), polls for results, and exits non-zero if thresholds aren't met.

Getting Started

From zero to deployed agent in 4 steps

1
Snowflake Setup
Run deploy/setup_snowflake.sql to create databases, warehouse, and roles
2
Configure GitHub Secrets
Add SNOWFLAKE_ACCOUNT, USER, PASSWORD, ROLE, WAREHOUSE to repo secrets
3
Local Development
dbt deps && dbt build --target dev to build the full stack locally
4
Open a PR
CI validates automatically. Merge deploys to production. Done.
Prerequisites: Snowflake account with Cortex Agent access, GitHub repo with Actions enabled, Python 3.11+ with dbt-snowflake.

Key Takeaways

  • Treat agents as deployable units — data models + semantic view + agent DDL belong together
  • Use dbt_semantic_view — materializes native Snowflake semantic views directly from dbt
  • Automate evaluation in CI — catch regressions before they reach production
  • Environment isolation via targets — dev and prod are identical in structure, different in data
  • Path-scoped triggers — workflows only fire when relevant files change
  • Score thresholds as quality gates — PRs cannot merge if the agent regresses
Bottom line: Every change to your data layer is automatically validated end-to-end — from dbt model correctness through semantic view integrity to agent answer quality — before reaching production.
