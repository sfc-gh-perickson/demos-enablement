Token-Level Deep Dive

The TOKENS_GRANULAR array in CORTEX_AGENT_USAGE_HISTORY provides a per-sub-request breakdown:

Structure of TOKENS_GRANULAR

-- Each element maps: request_id -> service_type -> model -> token counts
[{
  "request_id_abc": {
    "cortex_agents": {
      "claude-4-sonnet": {
        "input": 1800,
        "cache_read_input": 200,
        "cache_write_input": 0,
        "output": 600
      }
    },
    "start_time": "2026-07-01 09:00:00"
  }
}]

Token Categories

input

Tokens in the prompt sent to the model. Largest component of cost.

output

Tokens generated by the model response. Typically 2-3x the cost rate of input.

cache_read_input

Tokens served from prompt cache. Significantly cheaper than fresh input tokens.

cache_write_input

Tokens written to prompt cache for future reuse.

Query: Per-Model Breakdown

SELECT
    f.value:service_type::STRING AS service_type,
    f.value:model::STRING AS model_name,
    SUM(f.value:input::NUMBER) AS input_tokens,
    SUM(f.value:cache_read_input::NUMBER) AS cache_read,
    SUM(f.value:output::NUMBER) AS output_tokens,
    ROUND(SUM(f.value:cache_read_input::NUMBER)
        / NULLIF(SUM(f.value:input::NUMBER), 0) * 100, 1) AS cache_hit_pct
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY,
    LATERAL FLATTEN(input => TOKENS_GRANULAR) f
WHERE START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY 1, 2
ORDER BY input_tokens DESC;

Cortex Analyst Credits

When a Cortex Agent invokes Cortex Analyst as a tool, those costs appear in two places:

Within CORTEX_AGENT_USAGE_HISTORY

TOKENS_GRANULAR entries with service_type = 'cortex_analyst' show the analyst's token consumption per model.

METADATA:ai_functions_credits shows additional AI function credits.

CORTEX_ANALYST_USAGE_HISTORY

Hourly rollup view with CREDITS, REQUEST_COUNT, and USERNAME.

These credits roll into AI_SERVICES in METERING_DAILY_HISTORY.

Query: Analyst Credits by User

SELECT
    USERNAME,
    SUM(REQUEST_COUNT) AS total_requests,
    SUM(CREDITS) AS total_analyst_credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_ANALYST_USAGE_HISTORY
WHERE START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY 1
ORDER BY total_analyst_credits DESC;

Warehouse Compute Attribution

Token credits are only part of the cost. When Cortex Analyst generates SQL, it runs on a warehouse. That compute is a separate billing dimension tracked in QUERY_ATTRIBUTION_HISTORY.

Key Facts

  • CREDITS_ATTRIBUTED_COMPUTE = warehouse credits for executing the query (excludes idle time)
  • Latency: up to 8 hours for data to appear
  • Short queries (< ~100ms) may not appear in this view
  • Does NOT include: data transfer, storage, cloud services, or serverless costs

The Join Key: QUERY_TAG

The agent automatically tags its generated SQL queries with QUERY_TAG = 'cortex-agent-{REQUEST_ID}'. This enables a precise join between agent requests and warehouse compute -- no manual tagging required.

Query: Per-Request Warehouse Compute

SELECT
    a.REQUEST_ID,
    a.AGENT_NAME,
    COALESCE(SUM(q.CREDITS_ATTRIBUTED_COMPUTE), 0) AS warehouse_credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY a
LEFT JOIN SNOWFLAKE.ACCOUNT_USAGE.QUERY_ATTRIBUTION_HISTORY q
    ON q.QUERY_TAG = 'cortex-agent-' || a.REQUEST_ID
WHERE a.START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY 1, 2
ORDER BY warehouse_credits DESC;

Caveats

  • Queries < ~100ms don't appear in QUERY_ATTRIBUTION_HISTORY (show as 0 credits)
  • Up to 8-hour latency before attribution data appears
  • The QUERY_TAG pattern cortex-agent-{uuid} is set automatically by the agent runtime

Total Cost of a Request

A single agent request incurs costs across three dimensions:

Token Credits precise
+
AI Function Credits precise
+
Warehouse Credits estimated
=
Total Cost
ComponentPrecisionHow
Token creditsPreciseDirectly in CORTEX_AGENT_USAGE_HISTORY.TOKEN_CREDITS
AI function creditsPreciseDirectly in METADATA:ai_functions_credits
Warehouse computePreciseJoin via QUERY_TAG = 'cortex-agent-' || REQUEST_ID

Combined Query (via QUERY_TAG join)

SELECT
    a.REQUEST_ID,
    a.USER_NAME,
    a.AGENT_NAME,
    a.TOKEN_CREDITS AS ai_token_credits,
    COALESCE(a.METADATA:ai_functions_credits::NUMBER, 0) AS ai_fn_credits,
    COALESCE(SUM(q.CREDITS_ATTRIBUTED_COMPUTE), 0) AS warehouse_credits,
    a.TOKEN_CREDITS
        + COALESCE(a.METADATA:ai_functions_credits::NUMBER, 0)
        + COALESCE(SUM(q.CREDITS_ATTRIBUTED_COMPUTE), 0) AS total_credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY a
LEFT JOIN SNOWFLAKE.ACCOUNT_USAGE.QUERY_ATTRIBUTION_HISTORY q
    ON q.QUERY_TAG = 'cortex-agent-' || a.REQUEST_ID
WHERE a.START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY 1, 2, 3, 4, 5
ORDER BY total_credits DESC
LIMIT 10;

Note: warehouse_credits = 0 means the generated SQL ran in < ~100ms (below the attribution tracking threshold). The join itself is precise.

Per-User Attribution

Every request in CORTEX_AGENT_USAGE_HISTORY is tagged with USER_NAME, USER_ID, and USER_TAGS for chargeback.

Snowflake User Attribution

SELECT
    USER_NAME,
    AGENT_NAME,
    COUNT(*) AS request_count,
    SUM(TOKENS) AS total_tokens,
    SUM(TOKEN_CREDITS) AS total_credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY
WHERE START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY 1, 2
ORDER BY total_credits DESC;

Non-Snowflake User IDs (Multi-Tenant Apps)

In multi-tenant apps, USER_NAME is often a shared service account. Three approaches to track application-level user identity:

Session Attributes (agent:run API)

Pass variables with is_immutable_session_attribute: true. Readable via SYS_CONTEXT('SNOWFLAKE$SESSION_ATTRIBUTES', 'key'). Works with row access policies for tenant isolation.

Multi-Tenancy Docs

USER_TAGS

Apply Snowflake tags to users: ALTER USER svc SET TAG app_user = 'user-123'. These appear in the USER_TAGS array column and can be queried via LATERAL FLATTEN.

Tag-Based Cost Center Grouping

SELECT
    t.value:tag_value::STRING AS cost_center,
    COUNT(*) AS requests,
    SUM(TOKEN_CREDITS) AS credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY,
    LATERAL FLATTEN(input => USER_TAGS) t
WHERE t.value:tag_name::STRING = 'cost-center'
    AND START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY 1
ORDER BY credits DESC;

Resource Budgets

Snowflake supports tag-based resource budgets that monitor agent spend and take automated actions (alerts, access revocation) when thresholds are exceeded.

How It Works

  1. Create a tag and apply it to the Cortex Agent object
  2. Create a budget with a monthly credit limit
  3. Configure threshold actions (e.g., alert at 80%, revoke at 100%)
  4. Snowflake evaluates spending periodically and triggers actions

Setup Pattern

-- Apply cost-center tag to agent
ALTER AGENT IF EXISTS my_agent
    SET TAG cost_mgmt_db.tags.cost_center = 'finance';

-- Create budget with 500 credit/month limit
CREATE SNOWFLAKE.CORE.BUDGET my_agent_budget();
CALL my_agent_budget!SET_SPENDING_LIMIT(500);

-- Alert at 80%, revoke at 100%
CALL my_agent_budget!SET_NOTIFICATION_THRESHOLD(80);
CALL my_agent_budget!ADD_CUSTOM_ACTION(
    SYSTEM$REFERENCE('PROCEDURE', 'sp_revoke_agent_access(string, string)'),
    ARRAY_CONSTRUCT('my_agent', 'user_role'),
    'ACTUAL', 100
);

Enforcement latency: Up to 8 hours (or 2 hours with low-latency budgets enabled).

Important Caveats

  • ACCOUNT_USAGE views have up to 3-hour latency (sometimes longer)
  • QUERY_ATTRIBUTION_HISTORY can take up to 8 hours
  • Short queries (< ~100ms) may not appear in attribution views
  • AI_SERVICES in metering is a roll-up of multiple feature views -- do not sum overlapping views
  • Token credits and warehouse credits are separate billing dimensions
  • Set QUERY_TAG on agent sessions to enable compute attribution
