The Problem

The Cortex Agent agent:run API does not natively accept file attachments.

Content TypeSupportedNotes
type: "text"YesStandard text input
type: "image"LimitedBase64 for claude-sonnet-4-5+ only
type: "file"NoReturns an error; not a supported primitive
Key constraint: Raw binary file upload is not a supported content type in the agent:run API. Snowflake Intelligence's "+" button uses a proprietary internal pipeline that is not publicly accessible.

Key insight: The middleware does NOT parse the document. It uploads to stage and prepends a one-line hint. The agent autonomously decides if/when to read the file via its tool.

The UDF Tool: READ_STAGED_DOCUMENT

A SQL UDF registered as a generic tool on the agent.

CREATE FUNCTION READ_STAGED_DOCUMENT(filename VARCHAR)
RETURNS VARCHAR
LANGUAGE SQL
AS
$$
  SELECT COALESCE(
    AI_PARSE_DOCUMENT(
      TO_FILE('@DOC_UPLOADS', filename),
      {'mode': 'LAYOUT'}
    ):content::VARCHAR,
    '[Error: Could not parse document]'
  )
$$;
-- Agent spec (excerpt)
tools:
  - tool_spec:
      type: "generic"
      name: "read_document"
      description: "Read and parse a document from the upload stage."
      input_schema:
        type: object
        properties:
          filename: { type: string }
        required: [filename]

tool_resources:
  read_document:
    type: function
    identifier: "DB.SCHEMA.READ_STAGED_DOCUMENT"
    execution_environment:
      type: warehouse
      warehouse: MY_WH

The Middleware Pattern

Three responsibilities. No parsing logic.

1. Upload to Stage

Receive file from frontend. Convert .csv/.json to .txt (rename only). PUT to @DOC_UPLOADS.

2. Prepend Hint

Add a system-style text block: "The user uploaded 'reports/analysis.txt'. Use read_document to access it."

3. Forward to Agent

Pass thread_id + parent_message_id + the content blocks to agent:run.

// What the middleware sends to agent:run
{
  "thread_id": 1234,
  "parent_message_id": 0,
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "[User uploaded 'reports/q2_plan.txt'. Use read_document if relevant.]"},
      {"type": "text", "text": "Which region has the most aggressive growth target?"}
    ]
  }]
}

File Type Handling

AI_PARSE_DOCUMENT handles most formats. CSV/JSON just need a rename.

File TypeMiddleware ActionUDF Behavior
PDF, DOCX, PPTXUpload as-isAI_PARSE_DOCUMENT (LAYOUT)
TXT, HTMLUpload as-isAI_PARSE_DOCUMENT (LAYOUT)
JPEG, PNG, TIFUpload as-isAI_PARSE_DOCUMENT (OCR/LAYOUT)
CSV, JSON, MDRename to .txtAI_PARSE_DOCUMENT reads as text
Why rename? AI_PARSE_DOCUMENT does not support .csv/.json extensions. Renaming to .txt is a no-op on the content -- the function reads it as plain text, preserving the original structure (headers, delimiters, etc.).

Multi-Turn Conversations

Use threads. The file hint only goes in the first message.

Turn 1: Upload + Question

Create thread. Prepend file hint. Agent calls read_document and answers.

parent_message_id: 0

Turn 2+: Follow-up

No file hint needed. Agent retains document context from the thread history.

parent_message_id: <prev assistant_id>

// Turn 2: just the question, no file re-upload
{
  "thread_id": 1234,
  "parent_message_id": 456,  // from Turn 1 response metadata
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "What actions should we take in the Southeast?"}
    ]
  }]
}

Production Considerations

Context Window Limits

Large docs (100+ pages) may exceed the model's context. Consider adding a pages param to the UDF, or pre-chunking in the middleware.

Cost

AI_PARSE_DOCUMENT bills per page. The UDF is only invoked when the agent decides it needs the file -- no wasted parsing.

Caching

Store parsed content in a table keyed by file hash. Modify the UDF to check cache before calling AI_PARSE_DOCUMENT.

Security

Stage access governed by RBAC. Consider per-user paths: @DOC_UPLOADS/{user_id}/. UDF hardcodes the stage to prevent traversal.
