The Problem: Inconsistent Agent Selection

Users reach the same agents through multiple AI assistant surfaces. Each surface selects agents differently.

Developer Tools

Tool search may be ON by default. MCP tools deferred — only names visible before search. Shares ranking with every other connector the user has enabled.

Chat Interfaces

User-toggled tool access settings (Auto / On demand). Auto-deferral algorithms are not published. Behavior varies per user configuration.

Collaborative Assistants

Tool-loading behavior varies by platform. Agent visibility and selection logic is opaque from the server side.

Result: The same question routes to different agents (or fails to route at all) depending on which surface the user is on, what other connectors they have, and their local settings.

Root Cause

The agent-selection decision lives in the client harness, not in our platform.

What We Control

  • Tool descriptions in MCP server spec
  • Tool names and identifiers
  • Agent instructions and behavior

What We Don't Control

  • Whether tools are preloaded or deferred
  • Client-side search ranking algorithm
  • System prompt wrapping per surface
  • Competition with other user connectors
  • Per-user settings and session state
Key insight: Variance affects discovery, not execution. Once the right agent is invoked, the same Cortex Agent runs identically everywhere. The fix is to make discovery deterministic.

The Solution: Platform-Side Orchestration

Move agent selection out of the client and into Snowflake — where the agents already live.

Single Entry Point

One Supervisor Agent receives every request. Clients see exactly one tool, not N.

Server-Side Routing

The supervisor selects the right specialist inside Snowflake using stored procedure tools. No client-side variance.

Testable & Measurable

Routing decisions are evaluated with Cortex Agent Evaluations — regressions are caught before they reach users.

Implementation Pattern

The Stored Procedure Wrapper

CREATE OR REPLACE PROCEDURE RUN_SALES_AGENT(message STRING) RETURNS STRING LANGUAGE PYTHON RUNTIME_VERSION = '3.11' PACKAGES = ('snowflake-snowpark-python') HANDLER = 'run' EXECUTE AS OWNER AS $$ import json def run(session, message): body = json.dumps({ "messages": [{"role": "user", "content": [{"type": "text", "text": message}]}] }) result = session.sql(f""" SELECT SNOWFLAKE.CORTEX.DATA_AGENT_RUN( 'ROUTING_DEMO.ROUTING.SALES_ANALYST', '{body}' ) """).collect() return str(result[0][0]) if result else '' $$;
Why EXECUTE AS OWNER? The wrapper procedure runs with the owner's identity, resetting the caller context. Each specialist agent operates with its own grants — no privilege escalation chain.

Supervisor Agent Specification

CREATE OR REPLACE AGENT SUPERVISOR FROM SPECIFICATION $$ # Tools declare procedure wrappers as generic tools tools: - tool_spec: type: generic name: sales_agent description: "Revenue, sales forecasts, channel performance" input_schema: type: object properties: message: { type: string } required: ["message"] # Resources map tool names to stored procedures tool_resources: sales_agent: type: procedure identifier: ROUTING_DEMO.ROUTING.RUN_SALES_AGENT execution_environment: type: warehouse warehouse: ROUTING_DEMO_WH $$;

The supervisor's orchestration instructions define routing keywords per specialist. All routing logic is in one place, under our control.

Scaling to N Specialists

The pattern extends linearly. Each new specialist requires three additions:

1. Agent Definition

CREATE AGENT with domain-specific instructions, tools (semantic views, search services), and budget.

2. Wrapper Procedure

EXECUTE AS OWNER stored procedure calling DATA_AGENT_RUN for the new specialist.

3. Supervisor Tool Entry

Add a tool_spec + tool_resources entry to the supervisor's specification with routing keywords.

4. Evaluation Coverage

Add test queries to the evaluation dataset covering the new specialist's domain boundaries.

Production considerations: The supervisor adds ~1-3s of LLM reasoning before routing. Monitor token costs via CORTEX_AI_USAGE views. Run evaluations after any change to instructions or tool descriptions.
