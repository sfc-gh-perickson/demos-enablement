PII in Unstructured Text

Regulatory Compliance

GDPR, CCPA, HIPAA, and SOX all mandate that PII be masked or redacted before sharing, analytics, or long-term storage.

Scale Challenge

Millions of support tickets, medical notes, and chat transcripts arrive daily. Manual review is impossible at production scale.

Latency Requirements

Real-time applications need redacted text in milliseconds, not the seconds that LLM inference typically requires.

Accuracy Demands

Regex-based approaches miss context-dependent PII. "Jordan" is a name in one context but a country in another.

The naive approach: Calling an LLM to rewrite entire paragraphs is accurate but slow — output tokens are generated sequentially, and rewriting 500 words takes 3-5 seconds per record.

Approach 1: AI_REDACT

Managed, zero-config redaction

SELECT SNOWFLAKE.CORTEX.AI_REDACT(
  transcript,
  'redact'

FROM PII_REDACTION_DEMO.RAW.SUPPORT_TICKETS;

Detect Mode

Returns a JSON object identifying PII spans and their categories — useful for auditing what's present without modifying text.

Redact Mode

Returns the original text with PII replaced by category labels like [PERSON], [EMAIL], [PHONE_NUMBER].

Approach 2: AI_COMPLETE Extract+Replace

Custom structured extraction with typed labels

SELECT SNOWFLAKE.CORTEX.COMPLETE(
  'llama3.1-8b',
  'Extract all PII from this text. Return JSON with keys:
  names, emails, phones, addresses, ssns, credit_cards.
  Each key maps to an array of found values.
  Text: ' || transcript,
  {
    'response_format': {
      'type': 'json',
      'schema': {
        'type': 'object',
        'properties': {
          'names':        {'type': 'array', 'items': {'type': 'string'}},
          'emails':       {'type': 'array', 'items': {'type': 'string'}},
          'phones':       {'type': 'array', 'items': {'type': 'string'}},
          'addresses':    {'type': 'array', 'items': {'type': 'string'}},
          'ssns':         {'type': 'array', 'items': {'type': 'string'}},
          'credit_cards': {'type': 'array', 'items': {'type': 'string'}}
        }
      }
    }
  }
) AS extracted_pii
FROM PII_REDACTION_DEMO.RAW.SUPPORT_TICKETS;

Structured Output

Using response_format guarantees valid JSON — no parsing failures, no regex on free-text responses.

Typed Labels

Each PII category is extracted separately, enabling type-specific redaction (e.g., partial masking for phones, full removal for SSNs).

Model Flexibility

Choose your model: llama3.1-8b for speed, llama3.1-70b for accuracy, or claude-3.5-sonnet for complex documents.

Key advantage over AI_REDACT: Full control over extraction categories, custom labels, and the ability to do partial masking (e.g., showing last 4 digits of a phone number).

Why Rewriting is Slow

Asking the LLM to output the full redacted paragraph means generating every single word sequentially — even the words that don't change.

Why Extraction is Fast

Asking for only the PII values means the LLM outputs just the entities (a few tokens). String replacement in Python handles the rest instantly.

10x latency reduction — Extract PII values, then do deterministic string replacement. The LLM does what it's good at (understanding context), Python does what it's good at (string ops).

The UDF: REDACT_PII

Combining extraction + deterministic replacement

CREATE OR REPLACE FUNCTION PII_REDACTION_DEMO.ANALYTICS.REDACT_PII(input_text STRING)
RETURNS STRING
LANGUAGE PYTHON
RUNTIME_VERSION = '3.11'
PACKAGES = ('snowflake-snowpark-python')
HANDLER = 'redact_pii'
AS $$
import json
from snowflake.snowpark import Session

def redact_pii(input_text):
    session = Session.builder.getOrCreate()

    # Extract PII via structured LLM call
    prompt = f"""Extract all PII. Return JSON with keys:
    names, emails, phones, addresses, ssns, credit_cards.
    Text: {input_text}"""

    result = session.sql(f"""
        SELECT SNOWFLAKE.CORTEX.COMPLETE(
            'llama3.1-8b', '{prompt}',
            {{'response_format': {{'type': 'json'}}}}
        )""").collect()[0][0]

    pii = json.loads(result)

    # Deterministic replacement
    redacted = input_text
    label_map = {
        'names': '[PERSON]',
        'emails': '[EMAIL]',
        'phones': '[PHONE]',
        'addresses': '[ADDRESS]',
        'ssns': '[SSN]',
        'credit_cards': '[CREDIT_CARD]'
    }
    for category, label in label_map.items():
        for value in pii.get(category, []):
            redacted = redacted.replace(value, label)

    return redacted
$$;

Instant Replacement

String replacement is O(n) — no token generation overhead. The LLM only extracts the PII values, Python handles substitution.

Typed Labels

Each PII type gets a distinct label, making downstream analytics aware of what was redacted without exposing the data.

Deterministic

Same input always produces the same output. No LLM temperature variance in the redaction step itself.

  created_at,
  PII_REDACTION_DEMO.ANALYTICS.REDACT_PII(transcript) AS redacted_transcript,

-- Query the cache — no LLM, no latency
SELECT ticket_id, redacted_transcript, category
FROM PII_REDACTION_DEMO.ANALYTICS.REDACTED_TICKETS
WHERE priority = 'high'
ORDER BY created_at DESC;

Write-Time Cost

LLM inference happens once during ingestion or via a scheduled task. The cost is amortized across all subsequent reads.

Read-Time Speed

Queries hit a standard Snowflake table — micro-partition pruning, result caching, and columnar scan all apply.

Sub-second response times. Analysts query redacted data without waiting for LLM inference. The cache is just a table — standard Snowflake performance guarantees apply.

Write-Once, Read-Many

The cached approach pays the LLM cost once per record. Every subsequent read is pure warehouse compute — orders of magnitude cheaper.

Token Efficiency

The extract-only approach generates 10-20x fewer output tokens than rewriting full text, directly reducing per-call cost.

AI_REDACT Simplicity

Higher per-call cost but zero engineering overhead. For low-volume or exploratory use cases, the managed approach wins on total cost of ownership.

Production Patterns

Keeping the cache fresh and reliable

Tasks + Streams

Use a Snowflake Stream on the raw table to detect new inserts. A Task triggers the UDF only on new rows — no full-table rescans.

CREATE STREAM ticket_stream
  ON TABLE RAW.SUPPORT_TICKETS;

CREATE TASK redact_new_tickets
  SCHEDULE = '5 MINUTE'
  WHEN SYSTEM$STREAM_HAS_DATA('ticket_stream')
AS
  INSERT INTO ANALYTICS.REDACTED_TICKETS
  SELECT ticket_id, created_at,
    REDACT_PII(transcript), category, priority
  FROM ticket_stream;

Dynamic Tables

Let Snowflake manage the refresh. Define the transformation declaratively and set a target lag.

CREATE DYNAMIC TABLE REDACTED_TICKETS
  TARGET_LAG = '10 minutes'
  WAREHOUSE = REDACTION_WH
AS
  SELECT ticket_id, created_at,
    REDACT_PII(transcript) AS redacted,
    category, priority
  FROM RAW.SUPPORT_TICKETS;

Staleness Detection

Monitor cache freshness by comparing max timestamps between raw and redacted tables. Alert when lag exceeds SLA.

SELECT
  TIMESTAMPDIFF('minute',
    (SELECT MAX(created_at) FROM REDACTED_TICKETS),
    (SELECT MAX(created_at) FROM RAW.SUPPORT_TICKETS)
  ) AS lag_minutes;

Error Handling

Wrap redaction in TRY/CATCH. Route failures to a dead-letter table for manual review rather than blocking the pipeline.

Decision Framework

When to use each approach

Use AI_REDACT when...

  • You need quick, ad-hoc redaction
  • Standard PII categories suffice
  • Volume is low (< 100K records)
  • You don't need custom labels
  • Zero maintenance is the priority

Use Extract+Replace UDF when...

  • You need custom PII categories
  • Partial masking is required
  • Real-time responses under 1 second
  • You want model flexibility
  • Type-aware downstream processing

Use Pre-Computed Cache when...

  • Read-heavy analytics workloads
  • Sub-second query latency required
  • Same data queried repeatedly
  • Cost optimization at scale
  • Batch processing is acceptable
Best practice: Start with AI_REDACT for prototyping. Graduate to the UDF when you need customization. Add the cache layer when query volume or latency demands it.
