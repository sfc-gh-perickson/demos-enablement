The Problem

  • Models trained locally or in notebooks live as pickle files with no lineage
  • Moving data out of Snowflake for inference is slow and costly
  • Version tracking across environments is fragile and manual
  • Deploying models to production requires separate serving infrastructure

What Is the Model Registry?

Schema-Level Storage

Any Snowflake schema can act as a registry. Models are first-class objects alongside tables and views.

Versioned Artifacts

Each model has named versions with metadata, metrics, and dependency tracking built in.

Serverless Inference

Run predictions directly in Snowflake via SQL or Python — the model executes where the data lives.

Code Walkthrough

Register the model

from snowflake.ml.registry import Registry

# Open registry (any schema works)
reg = Registry(session=session,
    database_name="ML_REGISTRY_DEMO",
    schema_name="REGISTRY")

# Register the XGBoost model
mv = reg.log_model(
    model,
    model_name="xgboost_breast_cancer",
    version_name="v1",
    conda_dependencies=["xgboost", "scikit-learn"],
    sample_input_data=X_sample,
)

Run inference

# Predict directly in Snowflake
results = mv.run(X_sample.head(5))

What You Get

Version Management

Name versions, set defaults, compare metrics across iterations.

Dependency Tracking

Conda and pip dependencies are stored with the model and resolved at inference time.

Signature Inference

Input/output schemas are derived from sample data — no manual spec needed.

RBAC & Governance

Models inherit Snowflake's role-based access control. Share across teams with standard grants.
