The Problem

A generic agent gives generic answers. Users want responses relevant to what they're looking at right now.

Without Context

User asks "What should I focus on?" and gets a broad summary of all available data with no prioritization.

With Context

The agent knows the user is viewing rising churn on the Executive Dashboard, and immediately focuses on churn drivers and remediation.

Key insight: The same question produces different, more relevant answers when the agent knows what the user is currently viewing.

The Pattern

App Layer
Page state, role, visible metrics
→
Messages

→
Named Agent
Tools + model pre-configured
→
Response
Tailored to context
What changes per request: Only the system message content (page context).

What stays fixed: Agent object (tools, tool_resources, model, base instructions).

Agent Object (CREATE AGENT)

All configuration lives in the agent object. No tools or instructions in the runtime request.

CREATE AGENT CORTEX_AGENT_DEMO.ANALYTICS.ANALYTICS_AGENT FROM SPECIFICATION $$ models: orchestration: claude-sonnet-4-5 instructions: response: > You are an AI assistant embedded in a SaaS analytics platform. Be concise and actionable. Cite specific numbers. tools: - tool_spec: type: "cortex_analyst_text_to_sql" name: "analyst_tool" tool_resources: analyst_tool: semantic_view: "CORTEX_AGENT_DEMO.ANALYTICS.ANALYTICS_ASSISTANT" execution_environment: type: "warehouse" warehouse: "COMPUTE_WH" $$;

Context Injection via Messages

Dynamic page state goes into a system message. The user's question stays clean.

# The only thing that changes per request payload = { "messages": [ { "role": "system", "content": [{"type": "text", "text": context}], }, { "role": "user", "content": [{"type": "text", "text": question}], }, ], "stream": False, } # POST /api/v2/databases/.../agents/ANALYTICS_AGENT:run

Deployment

1. Run setup.sql

Creates database, tables, semantic view, agent object, and grants. One script, full environment.

2. Deploy Streamlit

snow streamlit deploy --replace pushes app.py and agent_client.py to Streamlit-in-Snowflake.

3. Auth handled by SiS

Uses _snowflake.send_snow_api_request() internally. No PATs or tokens at runtime.

Project files: setup.sql, snowflake.yml, app.py, agent_client.py, demo_notebook.ipynb

Next Steps

Adapt to Your Use Case

Replace mock data with real tables. Point the semantic view at your schema. The context injection pattern stays the same.

Add More Tools

Cortex Search for docs, custom UDFs for actions, data_to_chart for visualizations. All configured in the agent object.

Use Threads

Add thread_id + parent_message_id for multi-turn conversations with server-side history management.
