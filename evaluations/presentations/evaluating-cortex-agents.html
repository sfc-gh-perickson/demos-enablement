Evaluating Cortex Agents

A hands-on guide to measuring, improving, and trusting your AI agents in production.

Scenario: You're building a CMO-facing assistant that answers questions about campaign performance, budget allocation, and marketing strategy. The agent uses three tools: Cortex Analyst (structured data), Cortex Search (strategy documents), and an Agent Skill (executive summaries).

Two parts: Theory (why and what to evaluate) + Practice (how to evaluate and iterate in Snowflake)

Part 1

Theory: Why and What to Evaluate

The Trust Problem

An agent's answer may appear successful, but the path it took to get there may not be.

Hidden Failures

Agents can produce correct-looking answers through incorrect reasoning, wrong tool usage, or hallucinated intermediate steps that happen to reach the right conclusion.

Wasted Compute

Inefficient tool calling, redundant steps, and poor planning inflate latency and cost without any visible signal to end users or operators.

Wrong Decisions

Enterprise agents power business workflows serving thousands of users. Inaccurate outputs lead to incorrect business decisions at scale.

Eroded Trust

Without visibility into agent behavior, teams lose confidence in deployments. One undetected regression can undermine months of adoption progress.

The core challenge: Outcome-focused evaluation confirms whether an agent succeeded, but provides little insight into why it failed or how to fix it. We need evaluation that covers the full reasoning pipeline.

  • 95% error detection (vs. 55% baseline)
  • 86% error localization (vs. 49% baseline)
  • Coverage across low, medium, and high-impact failures

Key insight: Agent GPA makes agent behavior observable and debuggable. Instead of treating agents as black boxes, you can pinpoint exactly where in the reasoning chain quality degrades.

Evaluating Agent Tools & Skills

Our CMO Assistant composes three tool types. Each introduces distinct failure modes that require targeted evaluation strategies.

campaign_analytics (Cortex Analyst)

Queries structured campaign performance data — spend, revenue, impressions, clicks, conversions, ROI, CPC, and CPA by channel and time period.

Evaluate:

  • Was the generated SQL correct and scoped to the right time period?
  • Did the agent use this tool for quantitative questions?
  • Were results interpreted accurately (e.g., ROI expressed as a multiplier)?

strategy_search (Cortex Search)

Retrieves marketing strategy documents — budget allocation methodology, attribution models, performance benchmarks, and planning briefs.

Evaluate:

  • Was the right context retrieved? (retrieval relevance)
  • Did the agent ground its answer in retrieved content? (groundedness)
  • Was this tool used for qualitative/strategy questions?

executive_summary (Agent Skill)

Formats responses as executive summaries — headline insight, bullet points with key findings, and a recommended action.

Evaluate:

  • Was data gathered before formatting?
  • Was the output concise and board-appropriate?
  • Did the skill get invoked for summary/brief requests?

Tool Orchestration

The agent's planning layer decides which tools to invoke, in what order, and how to combine their outputs.

Evaluate:

  • Did the agent choose the right tool for the query intent?
  • Were multi-tool queries decomposed correctly? (e.g., "compare spend to strategy" needs both analytics + search)
  • For out-of-scope questions, did it avoid calling tools entirely?

Implication for evaluation datasets: Your eval set should include queries that exercise each tool individually (single_tool), queries requiring multi-tool coordination (multi_tool), and queries the agent should refuse (refusal). A dataset focused only on one intent type won't catch failures in the others.

Semantic View quality matters: If your semantic view (e.g., CMO_ANALYTICS) has poor descriptions, ambiguous metrics, or missing verified queries, the agent will generate incorrect SQL regardless of how good the orchestration LLM is. Evaluate your semantic view quality independently.

Designing Evaluation Datasets

Your evaluation is only as good as the data it tests against. Build datasets that reflect real-world usage distribution.

Cover All Intent Types

  • Happy paths — common questions the agent should handle well (single tool)
  • Multi-tool queries — questions requiring coordination between tools
  • Edge cases — specific, narrow queries (e.g., "CPA for email in March 2024")
  • Out-of-scope / refusal — questions the agent should decline

Prioritize High-Stakes Areas

Measure not only macro correctness but also intent-level performance. You need confidence that the agent behaves correctly in high-value, high-stakes scenarios — not just on average. Tag each question with its intent and process (complexity tier) to enable granular analysis.

Source Questions Strategically

Curate questions from SMEs who know the business domain, use synthetic generation to cover edge cases, or mine production logs if available. All three approaches are valid — the key is covering the full intent distribution.

Ground Truth Best Practices

  • Describe what correct looks like, not just a single "right answer"
  • Include acceptable tolerance (e.g., "Values within ±1% are acceptable")
  • Anchor to fixed time periods to avoid staleness
  • Include what the response should NOT contain
  • Add metadata: intent (get_metric, compare_channels, summarize, out_of_scope) and process (single_tool, multi_tool, refusal)

Dataset Format (Snowflake)

  INPUT_QUERY   VARCHAR,

Evaluation Rubrics & Metrics

A rubric is a collection of metrics that score the agent's performance. For the CMO Assistant, we use three metrics that cover correctness, reasoning quality, and tool selection.

Our Evaluation Rubric

MetricTypeWhat It Checks
answer_correctness Ground truth Compares agent output to expected answer
logical_consistency Reference-free Internal coherence of planning and execution
tool_selection Custom Did the agent choose the right tool(s)?

Logical consistency evaluates the full execution trace for internal coherence — no ground truth needed. Custom metrics let you evaluate domain-specific behavior.

Custom Metric Examples

  • Tool selection accuracy — chose the right tool for the task
  • Brand compliance — speaking in voice, no competitor mentions
  • Context relevance — did RAG retrieve correct documents
  • Groundedness — claims supported by retrieved context
  • Response completeness — addressed all parts of the query
  • Citation quality — references point to real sources
# Custom tool_selection metric for the CMO Assistant
metrics:
  - "answer_correctness"
  - "logical_consistency"
  - name: "tool_selection"
    score_ranges:
      min_score: [1, 3]
      median_score: [4, 6]
      max_score: [7, 10]
    prompt: |
      Evaluate whether the agent selected the correct tool(s) for the user's query.
      User query: {{input}}
      Tools used: {{tool_info}}
      Expected behavior: {{ground_truth}}
      Agent response: {{output}}

      Rate from 1-10:
      1-3 = Wrong tool selected or failed to use a tool when needed
      4-6 = Partially correct (right primary tool but missed secondary)
      7-10 = Optimal tool selection for the query intent

      Criteria:
      - campaign_analytics for quantitative questions (spend, revenue, ROI)?
      - strategy_search for qualitative questions (methodology, guidelines)?
      - Both tools for multi-faceted questions?
      - No tools called for out-of-scope questions?

Template variables available: {{input}}, {{output}}, {{ground_truth}}, {{tool_info}}, {{duration}}, {{span_type}}, {{llm_model}}, {{error}}, {{status}} — the full agent execution trace is always provided to the LLM judge as context.

LLM-as-a-Judge Methodology

Evaluation at scale requires automated scoring. LLM judges grade agent responses against your rubric — but they must be calibrated to match human judgment.

Trace-Level vs. Step-Level

Trace-Level Evaluation

Did the agent produce the correct final output? Evaluates the end-to-end result against ground truth.

Step-Level Evaluation

Did the agent use the correct tools with the correct parameters at each step? Evaluates intermediate reasoning and execution decisions.

Both are necessary: An agent can reach the right answer through wrong steps, or take all the right steps but produce a poor final answer.

Judge Calibration Process

The LLMAJ Tuning Loop

  1. Collect agent traces (question + trace + response triples)
  2. Have human SMEs grade them across your rubric
  3. Run LLM judges with initial prompts on the same data
  4. Measure correlation using Cohen's Kappa
  5. Iterate judge prompts until 80%+ correlation on dev/test splits

Why calibration matters: An uncalibrated LLM judge introduces uncertainty into your metrics. By achieving 80%+ Cohen's Kappa correlation with human annotators, you reduce the error bars on scores and can trust automated evaluations to approximate expert judgment.

Practice: How to Evaluate and Iterate

Build the Agent

The CMO Assistant is a multi-tool Cortex Agent with orchestration instructions that guide tool selection and response formatting.

CREATE AGENT CMO_ASSISTANT
FROM SPECIFICATION $$
models:
  orchestration: auto
instructions:
  response: |
    You are a CMO assistant that helps marketing leaders understand
    campaign performance, budget allocation, and strategic recommendations.
    Be concise and data-driven. Express ROI as a multiplier (e.g., 3.2x).
  orchestration: |
    For quantitative questions (spend, revenue, ROI), use campaign_analytics.
    For qualitative questions (strategy, methodology), use strategy_search.
    For executive summaries, gather data first, then format as a brief.
tools:
  - tool_spec:
      type: cortex_analyst_text_to_sql
      name: campaign_analytics
      description: "Query structured campaign performance data..."
  - tool_spec:
      type: cortex_search
      name: strategy_search
      description: "Search marketing strategy documents..."
tool_resources:
  campaign_analytics:
    semantic_view: CMO_EVAL_LAB.PUBLIC.CMO_ANALYTICS
  strategy_search:
    name: CMO_EVAL_LAB.PUBLIC.STRATEGY_SEARCH_SVC
$$

Key design choices: The orchestration instructions are intentionally brief in v1. We'll use evaluation results to identify where more explicit guidance is needed, then iterate.

Inspect Results & Iterate

Use evaluation results to identify the weakest areas, then make a targeted improvement. One change at a time.

Identify Failure Modes

Common weaknesses for our CMO Agent baseline:

  • Multi-tool coordination — the agent doesn't combine analytics + search for comparison questions
  • Out-of-scope handling — the agent attempts to answer questions it should refuse
-- Slice results by process tier
SELECT
  GROUND_TRUTH:process::VARCHAR AS PROCESS,
  METRIC_NAME,
  ROUND(AVG(EVAL_AGG_SCORE), 2) AS SCORE
FROM TABLE(GET_AI_EVALUATION_DATA(...))
GROUP BY ALL ORDER BY SCORE

Investigation Signals

  • Low answer correctness → improve instructions/tools
  • Low logical consistency → simplify system prompt
  • Low tool selection → add explicit routing rules
  • Production failures → add those queries to eval set

Read the explanations: LLM judges produce explanations for each score. Use these to understand what went wrong rather than guessing at improvements.

-- Fix: Add explicit TOOL SELECTION RULES to orchestration instructions
ALTER AGENT CMO_ASSISTANT MODIFY LIVE VERSION SET SPECIFICATION = $$
...
instructions:
  orchestration: |
    TOOL SELECTION RULES (follow strictly):
    1. QUANTITATIVE questions (spend, revenue, ROI) -> campaign_analytics
    2. QUALITATIVE questions (strategy, methodology) -> strategy_search
    3. COMPARISON questions referencing data AND strategy -> use BOTH tools
    4. EXECUTIVE SUMMARY requests -> gather data first, then format
    5. OUT-OF-SCOPE questions -> DO NOT call any tool. Politely decline.

    MULTI-TOOL COORDINATION:
    - When a question requires both data and context, ALWAYS call both tools.
    - Example: "How does spend compare to strategy?" needs analytics + search.
...
$$

Then re-evaluate: Commit the change, run the evaluation again with a new run name (improved-v2), and compare scores side-by-side. Look for improvement in multi_tool and refusal process tiers specifically.

Score History Table

CREATE TABLE EVAL_SCORE_HISTORY (
  RUN_NAME      VARCHAR,
  RUN_TIMESTAMP TIMESTAMP_TZ,
  METRIC_NAME   VARCHAR,
  AVG_SCORE     FLOAT,
  MIN_SCORE     FLOAT,
  MAX_SCORE     FLOAT,
  NUM_RECORDS   INT
);

After each eval run, insert aggregated scores. This creates a time-series of agent quality you can trend and alert on.

Snowflake Task

CREATE TASK DAILY_EVAL_CHECK
  WAREHOUSE = CMO_EVAL_WH
  SCHEDULE = '1440 MINUTE'
AS CALL RUN_EVAL_AND_STORE_SCORES(
  'daily-' || TO_CHAR(
    CURRENT_DATE(), 'YYYYMMDD')
);

The stored procedure runs EXECUTE_AI_EVALUATION, waits for completion, then inserts scores into the history table.

-- Regression detection: compare latest run to previous
WITH latest AS (
  SELECT METRIC_NAME, AVG_SCORE
  FROM EVAL_SCORE_HISTORY
  WHERE RUN_TIMESTAMP = (SELECT MAX(RUN_TIMESTAMP) FROM EVAL_SCORE_HISTORY)
),
previous AS (
  SELECT METRIC_NAME, AVG_SCORE
  FROM EVAL_SCORE_HISTORY
  WHERE RUN_TIMESTAMP = (SELECT MAX(RUN_TIMESTAMP) FROM EVAL_SCORE_HISTORY
    WHERE RUN_TIMESTAMP < (SELECT MAX(RUN_TIMESTAMP) FROM EVAL_SCORE_HISTORY))
)
SELECT l.METRIC_NAME, previous.AVG_SCORE AS PREV, l.AVG_SCORE AS CURRENT,
  ROUND(l.AVG_SCORE - previous.AVG_SCORE, 4) AS DELTA
FROM latest l JOIN previous ON l.METRIC_NAME = previous.METRIC_NAME
WHERE l.AVG_SCORE < previous.AVG_SCORE - 0.05 -- 5% drop threshold

Key distinction: Monitoring measures operational health (did the SQL execute? how long?). Scheduled evaluation measures correctness (did it return the right answer?). A query that executes successfully but returns wrong results is invisible to monitoring.

Human Feedback Integration

LLM-as-judge gives you scalable automated scoring. Human feedback tells you what users actually experience. Connect both to close the improvement loop.

Query Observability Events

All agent activity including user feedback is captured in:

SNOWFLAKE.LOCAL.AI_OBSERVABILITY_EVENTS

Filter for RECORD:name = 'CORTEX_AGENT_FEEDBACK' to find thumbs-up/thumbs-down signals with optional text messages.

Classify Negative Feedback

Use CORTEX.COMPLETE to automatically categorize negative feedback text into failure buckets:

  • Wrong tool selected
  • Incomplete answer
  • Format/style issue
  • Hallucinated content

Active Sampling

Identify negative-feedback sessions, pull the full trace, and promote those queries into your evaluation dataset as new test cases.

Production failures become the highest-value eval questions — they represent real user pain points.

-- Query user feedback from observability events
SELECT
  RECORD:'cortex_agent.request_id'::VARCHAR AS REQUEST_ID,
  RECORD:'cortex_agent_feedback.positive'::BOOLEAN AS POSITIVE,
  RECORD:'cortex_agent_feedback.feedback_message'::VARCHAR AS MESSAGE,
  RECORD_ATTRIBUTES:'snow.cortex.agent.name'::VARCHAR AS AGENT_NAME
FROM TABLE(SNOWFLAKE.LOCAL.GET_AI_OBSERVABILITY_EVENTS(
  DATEADD('day', -7, CURRENT_TIMESTAMP()), CURRENT_TIMESTAMP()
))
WHERE RECORD:'name' = 'CORTEX_AGENT_FEEDBACK'

The improvement cycle: Negative feedback → classify failure type → add question to eval dataset → iterate agent instructions → re-evaluate → promote. Every thumbs-down is an opportunity to strengthen your evaluation suite.

Threshold Gate Query

SELECT
  METRIC_NAME,
  ROUND(AVG(EVAL_AGG_SCORE), 4) AS SCORE,
  CASE
    WHEN METRIC_NAME = 'answer_correctness'
      AND AVG_SCORE < 0.70 THEN 'FAIL'
    WHEN METRIC_NAME = 'logical_consistency'
      AND AVG_SCORE < 0.60 THEN 'FAIL'
    WHEN METRIC_NAME = 'tool_selection'
      AND AVG_SCORE < 0.65 THEN 'FAIL'
    ELSE 'PASS'
  END AS GATE_STATUS
FROM TABLE(GET_AI_EVALUATION_DATA(...))
GROUP BY METRIC_NAME
